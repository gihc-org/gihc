## Kort resumé

tosproget hjemmeside. Arbejdet omfattede også visuel identitet, et

## Arkitektur og tekniske beslutninger

- Hjemmesiden er statisk og serveres med Nginx fra en container.
- Kubernetes-workloaden kører i namespace `gihc-site`.
- Trafikken går gennem ingress-nginx.
- TLS udstedes og fornyes med cert-manager og Let’s Encrypt.
- Produktionsimages pinnes til et uforanderligt SHA-tag.
- Dockerfile bruger et Node-buildtrin til Eleventy og et separat
  unprivileged Nginx-runtime-image.
- GitHub Actions bygger og publicerer containerimages til GHCR.
- Lokal k3s optager port 6443; VPS-tunnelen bruger derfor port 16443.

## Sikkerhed

En sikkerhedsgennemgang fandt en god grundsikkerhed, men også et forældet
Nginx-runtime-image med kendte, rettede sårbarheder.

Gennemførte tiltag:

- Opgraderede runtime-imaget fra Nginx 1.27 til Nginx 1.31.
- Trivy-scanningen af det nye image viser 0 HIGH- og 0 CRITICAL-fund.
- Tilføjede CVE-scanning som obligatorisk gate i GitHub Actions.
- Pinnede GitHub Actions til commit-SHA’er.
- Tilføjede ugentlige Dependabot-opdateringer for npm, Actions og Docker.
- Aktiverede Pod Security `restricted` i namespace.
- Tilføjede NetworkPolicy, som kun tillader ingress-trafik fra ingress-nginx
  til port 8080 og blokerer pod-egress.
- Strammede Content Security Policy med `frame-src 'none'` og
  `manifest-src 'none'`.
- Oprettede CAA-record, så kun Let’s Encrypt må udstede certifikater.
- Bekræftede, at HTTP-metoderne POST, OPTIONS og TRACE afvises, og at
  følsomme stier samt path traversal ikke eksponeres.
- `npm audit` viste 0 kendte afhængighedssårbarheder.

DNSSEC var ikke aktiveret ved sessionens afslutning og kræver afklaring hos
Simply.com.

## E-mail

- Opsatte en kodebaseret Migadu-integration via
  `scripts/setup-migadu-mail.py`.
- Aktiverede domænet hos Migadu og oprettede postkassen
  `mail@gihc.online`.
- Migadus diagnostik bestod for domæneverifikation, nameservere, SPF, MX og
  DKIM.
- De eksisterende Resend/SES-records på `send.gihc.online` blev ikke ændret.
- DMARC blev suppleret med aggregeret rapportering og stram alignment, mens
  policyen fortsat er `p=none`, indtil mailheadere er verificeret.
- En udgående testmail blev placeret i Gmail-spam. DNS-autentificeringen ser
  korrekt ud, så næste analyse skal bruge de fulde mailheaders og
  afsenderomdømme.
- Afsenderadressen skal opvarmes med almindelig, personlig korrespondance,
  og Gmail skal markere den som “Ikke spam” og tilføje den til kontakter.

API-nøgler, adgangskoder, private kontaktoplysninger og andre hemmeligheder
indgår ikke i dette referat. Credentials opbevares i `pass` og Kubernetes
Secrets.

5. Undersøg DNSSEC hos Simply.com.
